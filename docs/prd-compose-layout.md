# 产品需求变更：漫画合成版式（分格装框 + 布局规则）

> 版本：v1.0  
> 日期：2026-08-25  
> 状态：待开发（需求已确认，尚未改代码）  
> 范围：自动化创作成品图 `ComposeService`（`composed.png` / `composedLayout`）  
> 关联现状说明：[`server-overview.md`](./server-overview.md) 第 3.6 节  
> 参考问题：当前合成偏「宽图竖贴」，缺少漫画格感；4/6/8 格布局与目标两列版式不符

---

## 1. 背景与结论

### 1.1 背景

真正交付的条漫/多格漫，是 **多张分镜图按固定版式合并成一张成品图**，而不是让模型「一键画好整张多分格」。

当前流水线在「分格生图」上方向正确：

```text
每格单独生图（panel_N.png）→ 程序合成（composed.png）
```

但 **合成样式与布局有偏差**：

| 现状 | 问题 |
|------|------|
| 无论 4/6/8 一律单列竖拼 | 4/6/8 目标应为 **两列网格** |
| 格间仅细灰分隔线 | 不像漫画格（缺黑框、明确 gutter） |
| 顶部固定标题条 | 与常见两格/多格漫观感不一致（可改为可选） |
| 单格 16:9 | **保留**，作为统一画幅 |

### 1.2 需求结论（已拍板）

1. **继续**「每格固定画幅 → 再按模板合并」，不改成模型一键多分格。  
2. **单格画幅固定 16:9**（与现自动化一致，如 960×540）。  
3. **布局按格数分支**：  
   - **1～3 格**：单列竖拼  
   - **4 / 6 / 8 格**：两列网格合并  
4. **视觉风格固定**：同一套黑框、间距、页边距；只随格数变行列，不换「厂牌」样式。

### 1.3 非目标（本期不做）

- 改 Agent / 分镜 Prompt 叙事结构（可另开需求）  
- 模型生成「一张图里自带多格」  
- 自定义创作（`custom_comic`）画幅选项大改（可后续对齐同一套 Compose 模板）  
- 支付、鉴权

## 2. 产品目标

| 目标 | 说明 |
|------|------|
| 成品像漫画页 | 每格有清晰黑框与 gutter，整体白底、边距统一 |
| 布局符合格数规则 | 1～3 竖排；4/6/8 两列 |
| 风格可复用 | 常量模板化，避免每篇合成观感漂移 |
| 可单格重绘 | 仍基于独立 `panel_N.png`，合成只读文件拼版 |

---

## 3. 版式规范（验收标准）

### 3.1 公共样式常量（建议值，实现可微调但需全站统一）

| 项 | 建议值 | 说明 |
|----|--------|------|
| 单格内容区 | 960 × 540 | 16:9；生图结果 Fit 进该框（不拉伸变形；不足边 letterbox 或居中裁切，二选一写死） |
| 黑框 | 约 3～6px | 画在格外或格边缘，需每格可见 |
| gutter（格间距） | 约 12～16px | 用留白，**不要**再用细灰线代替格子感 |
| 页边距 padding | 约 16px | 画布四周 |
| 背景 | 白 | |
| 标题条 | 默认关闭或可选 | 开启时高度固定（如 64～80px），不影响格布局算法 |

### 3.2 布局规则

```text
若 panelCount <= 3：
  cols = 1
  rows = panelCount
否则（4 / 6 / 8）：
  cols = 2
  rows = ceil(panelCount / 2)
```

格序号 `i`（从 0 起）：

```text
col = i % cols
row = i / cols
x = padding + col * (panelW + gutter)
y = padding (+ 标题高) + row * (panelH + gutter)
```

### 3.3 阅读顺序

公众号常用：**先行内从左到右，再下一行**。

```text
① → ②
③ → ④
…
```

（若未来要「先右后左」，需另开需求改坐标与文案，本期不做。）

### 3.4 各格数示意图

#### 1～3 格：单列竖拼

```text
1 格:     2 格:        3 格:
┌───┐     ┌───┐        ┌───┐
│ ① │     │ ① │        │ ① │
└───┘     ├───┤        ├───┤
          │ ② │        │ ② │
          └───┘        ├───┤
                       │ ③ │
                       └───┘
```

#### 4 格：两列 × 两行

```text
┌─────┬─────┐
│ ①   │ ②   │
├─────┼─────┤
│ ③   │ ④   │
└─────┴─────┘
```

#### 6 格：两列 × 三行

```text
┌─────┬─────┐
│ ①   │ ②   │
├─────┼─────┤
│ ③   │ ④   │
├─────┼─────┤
│ ⑤   │ ⑥   │
└─────┴─────┘
```

#### 8 格：两列 × 四行

```text
┌─────┬─────┐
│ ①   │ ②   │
├─────┼─────┤
│ ③   │ ④   │
├─────┼─────┤
│ ⑤   │ ⑥   │
├─────┼─────┤
│ ⑦   │ ⑧   │
└─────┴─────┘
```

### 3.5 画布尺寸参考（padding=16，gutter=16，无标题，单格 960×540）

| 格数 | 列×行 | 约宽 | 约高 |
|------|-------|------|------|
| 1 | 1×1 | 992 | 572 |
| 2 | 1×2 | 992 | 1128 |
| 3 | 1×3 | 992 | 1684 |
| 4 | 2×2 | 1968 | 1128 |
| 6 | 2×3 | 1968 | 1684 |
| 8 | 2×4 | 1968 | 2240 |

> 产品当前创建选项为 **4 / 6 / 8**；1～3 的规则一并写入，便于以后开「两格段子」等，避免再次改布局语义。

### 3.6 台词与合成职责边界

| 阶段 | 职责 |
|------|------|
| 单格生图后（`captionTextMode`） | 在 `panel_N.png` 上叠 top / bubble / none |
| 合成 | **只**装框、摆格、拼成品；不重新发明一套排版文案 |

推荐默认文案模式保持可配；视觉验收以「格子清晰 + 布局正确」为主。

## 4. 与现状代码的差距（改动动机）

| 模块 | 现状 | 目标 |
|------|------|------|
| `service/compose_service.go` | 单列竖拼 + 灰线 + 顶栏标题 | 按 §3 分支布局 + 黑框 + 统一 gutter |
| `composedLayout.format` | `"long_image"` | 可保留或细分为 `strip_vertical` / `grid_2col`（可选，前端不依赖也可暂不改） |
| 前端文案 | 「16:9 分镜竖向拼接成长图」 | 改为「16:9 分镜按格数模板合成（≤3 竖排，4/6/8 两列）」 |
| `panelCount` 选项 | 仅 4/6/8 | 本期可不加 1～3；布局代码需兼容规则 |

**不改动**：分镜 Agent、逐格 `ImageService`、单格重绘 API、人机确认卡点。

## 5. 技术方案要点（实现时对照）

### 5.1 主要改动文件

1. `server/internal/service/compose_service.go` — 布局算法与绘制（黑框、背景、可选标题）  
2. （可选）抽常量到 `common` 或同文件 `const`，便于单测画布宽高  
3. `web/src/pages/user/create/index.tsx` — 步骤说明文案与合成预览旁提示  
4. （可选）`docs/server-overview.md` — 合成小节与版式同步一句  

### 5.2 建议实现步骤

```text
1. 写 layout(panelCount) → cols, rows, canvasW, canvasH
2. 替换灰线为：白底 + 每格 Fit + 矩形黑描边
3. 按 §3.2 计算每格 (x,y)
4. 标题条改为开关（默认关）或配置项
5. 用 4/6/8 三套本地 panel 图目测验收；有单测则断言画布尺寸
6. 更新前端「排版合成」说明文案
```

### 5.3 回归注意

- `regenerate-panel` 后再次 `Compose` 必须仍符合新版式  
- COS 上传路径与 `previewUrl` 不变即可  
- 公众号发布仍吃 `composed.png`，注意 **4/6/8 变两列后图变更宽**，预览区样式勿写死过窄导致难看（前端预览 `max-width: 100%` 一般可接受）

## 7. 优先级建议

相对鉴权 / 支付：本需求为 **体验向、可独立上线**，不阻塞登录与充值；与创作主路径强相关，可在鉴权 P0 并行或紧随其后做。

建议排期：**P0 合成布局 + 黑框模板** → P1 标题开关与前端文案 → P2 自定义创作对齐同一 Compose。
