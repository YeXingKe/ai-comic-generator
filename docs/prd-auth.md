## 1. 背景与目标

### 1.1 背景

当前登录为 **Redis Session + Cookie**，业务接口多数有 `AuthCheck`，前端有路由守卫。作为内测可用，但存在：密码哈希偏弱、调试加密接口公开、禁用账号不即时失效、Cookie/CORS 配置不足、前端未统一处理未登录等问题。

### 1.2 产品目标

| 目标 | 说明 |
|------|------|
| 可公网基线 | 密码、Session、禁用、跨域达到上线前安全基线 |
| 体验一致 | 未登录 / 被踢下线时自动回到登录页，无半失效状态 |
| 保持架构 | 继续使用 Redis Session，不强制改为 JWT |

### 1.3 非目标

- 微信 / 手机号 OAuth（可后续）
- 整站 JWT 无状态改造
- 完整 CSRF Token 体系（P0 用 SameSite 即可；P1 再增强）
- 支付、充值（独立文档，后置）

## 2. 用户可感知场景

### 场景 A：正常登录使用

用户登录后访问创作、个人中心等；关闭浏览器再打开，在 Session 有效期内仍保持登录（具体时长由配置决定）。

### 场景 B：账号被管理员禁用

1. 管理员将用户 `status` 设为禁用  
2. 该用户**下一次任意需登录接口**即失败  
3. 前端清理本地登录态并跳转登录页；提示「账号已被禁用」更佳  

### 场景 C：登录态失效 / 未登录调接口

1. Session 过期或未登录访问受保护接口  
2. 前端统一跳转 `/user/login`，可带回跳地址 `from`  

### 场景 D：修改密码

1. 用户修改密码成功  
2. 旧登录会话失效，需使用新密码重新登录（推荐体验）  

### 场景 E：登录防刷（P1）

短时间内同一账号或 IP 多次失败 → 短暂限制，提示稍后再试。

## 3. 功能需求

### 3.1 P0（必须先完成）

| 编号 | 需求 | 用户侧表现 |
|------|------|------------|
| A1 | 关闭公开「密码加密调试」能力 | 无感知；攻击面减少 |
| A2 | 密码改为不可逆强哈希（bcrypt 等），旧用户平滑迁移 | 仍用原密码登录，无强制全员改密 |
| A3 | Session Cookie 具备 HttpOnly / SameSite / 可配置 Secure | 无感知 |
| A4 | 禁用账号即时失效 | 见场景 B |
| A5 | CORS 允许源可配置 | 开发/生产域名可分别配置 |
| A6 | 前端统一处理未登录 | 见场景 C |

### 3.2 P1（鉴权增强，可紧随 P0）

| 编号 | 需求 | 用户侧表现 |
|------|------|------------|
| A7 | 登录失败限流 | 频繁失败时提示稍后再试 |
| A8 | 登出 / 改密彻底清理 Session | 改密后需重登；登出后 Cookie 失效 |
| A9 | 鉴权失败响应风格与项目统一 | 前端处理更简单（建议 HTTP 200 + 业务码，或前后端约定清晰） |

## 4. 验收标准（P0）

- [ ] 无法通过公开接口拿到「明文密码 → 库内哈希」的调试结果  
- [ ] 新注册 / 改密后的密码以强哈希存储（非裸 MD5）  
- [ ] 仍使用旧 MD5 的存量用户可用原密码登录，且登录后可自动升级哈希  
- [ ] 管理员禁用用户后，该用户旧 Session 无法再调需登录接口  
- [ ] 前端遇到未登录（HTTP 401 或业务码 `40100`）会清空登录态并跳转登录页  
- [ ] Session 的 `secret` / Cookie 安全选项可配置；example 中无弱默认生产密钥  
- [ ] CORS Origin 来自配置，不再写死唯一本地地址（至少支持配置多项）

## 6. 风险

| 风险 | 应对 |
|------|------|
| 旧密码迁移失败导致无法登录 | 登录双读（bcrypt / 旧 MD5）；迁移写库失败应打日志但不阻断当次登录（或按技术方案严格处理） |
| Secure Cookie 在本地 HTTP 导致无法带 Cookie | 开发环境 `secure: false`，生产 `true` |
| 前后端 401 形态不一致 | 技术方案明确兼容策略 |

## 7. 与现有能力映射

| 现有能力 | 关系 |
|----------|------|
| Redis Session + `AuthCheck` | 保留并加固 |
| `user.status` | 每次鉴权校验 |
| 前端 `RequireAuth` / `RequireAdmin` | 保留；真实权限仍以服务端为准 |
| `/user/encrypt/password` | P0 删除或锁定 |
